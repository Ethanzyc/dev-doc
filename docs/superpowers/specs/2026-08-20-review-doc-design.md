# 设计：评审版技术方案（review doc）

> 2026-08-20 确认稿。为 dev-doc 增加面向技术评审的衍生文档：主方案确认后生成、主方案变更后同步、任务级可关闭。

## 背景与问题

主产物 `<feature>技术方案.md` 的信息密度为**编码 AI** 设计：完整 DDL、字段级 schema、索引论证、末尾"实现速查"索引。它不适合内部技术评审——评审听众是产品、测试、前端和后端其他人，需要的是"15 分钟跟上演进逻辑并拍板"，密度高反而妨碍讲解。

## 目标

1. 方案确认（Phase 5 交付 checkpoint）后，可从主方案生成一份面向评审的精简版
2. 评审版存在时，主方案任何变更自动同步
3. 提供任务级开关，可关闭评审版生成

## 非目标

- 不做章节级增量同步（评审版与主方案章节非一一映射，切片规则复杂易错）——同步一律**整篇重生成**
- 不做项目级/全局配置文件（换任务仍会询问，YAGNI）
- 评审版**不可手动编辑**：单向衍生品，主方案是唯一事实源（防双轨漂移）

## 定位原则

**主方案给编码 AI 看契约，评审版给人讲决策。**

## 评审版内容结构（8 节，按讲解顺序）

| # | 章节 | 来源 | 内容与密度 |
|---|---|---|---|
| 1 | 需求 | 主方案 1+2 合并 | 一段话：做什么、为什么 |
| 2 | 整体设计思路 | 主方案 3.1 + 3.4 | 架构图 + 设计主线；**状态机融入**（流转图 + 触发条件精简版） |
| 3 | 数据模型 | 主方案 3.2 | DDL 保留；涉及存量迁移时附 DML |
| 4 | 接口改动 | 主方案 3.3 + 4 的接口变更行 | **新增接口给完整 schema**（前端第一次见），**变更接口只给 diff**（"变更前 → 变更后"对照） |
| 5 | 关键流程 | 主方案 3.5 | 时序图 + 步骤 |
| 6 | 测试影响 | 主方案 4 + plan.md 影响范围推导 | 本次变更的测试点 + **受影响的现有功能清单（回归范围）**——唯一需要增量推理（非直接摘录）的一节 |
| 7 | 风险评估 | 主方案 8 | 简化，只留评审要拍板的 |
| 8 | 工时评估 | 主方案 9 | 表格照搬 |

裁剪细则：

- **图直接复用**主方案的架构图/时序图/状态图（已过 mermaid 自检，不重画）
- **有则写无则跳过**：轻方案没有状态机/迁移/接口变更就不硬凑空节
- **配方适配**：multi-task 的子任务依赖/上线顺序并入"整体设计思路"或"关键流程"；greenfield 以设计思路为核心，无接口改动则跳过第 4 节

## 机制设计

### 触发与生命周期

```
Phase 5.3 交付 checkpoint
  └─ 决策项新增：评审版？
       ├─ 生成（推荐）→ 写 <feature>技术方案-评审版.md，plan.md 记"评审版：已生成"
       └─ 不生成 → plan.md 记"评审版：关闭"，本任务后续不再问
```

- **关闭入参**：用户激活 skill 时或任意时点说"不要评审版"→ plan.md 记录，**任务级**生效（换任务仍会询问）
- **产物**：`dev-doc/tasks/<feature>/<feature>技术方案-评审版.md`
- **文件头标注**："本文件为《xxx技术方案.md》的评审版衍生品，以主方案为准，请勿直接编辑"

### 同步机制

- 任务恢复（前置步骤「继续」路径）时**检测评审版文件存在** → 本次会话任何主方案变更落盘后，**立即整篇重生成**评审版并告知用户（变更本身已经过确认，重生成是机械操作，不攒到 checkpoint）
- plan.md 任务元信息记录评审版状态（未生成 / 已生成 / 关闭），跨会话可追溯

### 生成规则载体

新 reference 文件 `references/review-doc.md` 承载 8 节裁剪规则；SKILL.md 只加挂载点（Phase 5.3 决策项、继续路径检测），不把规则内联进主流程。

## 错误处理

| 场景 | 处理 |
|---|---|
| 评审版某节来源缺失（主方案无状态机/迁移等） | 跳过该节，不算错误 |
| 评审版文件存在但 plan.md 未记录（用户手动建过） | 询问用户：采信文件还是按新生成覆盖 |
| 主方案变更后重生成时主方案自身不完整 | 不生成，fail fast 提示先补全主方案 |

## 测试计划（evals 本地体系）

新增一条测试路径（生成 + 变更同步），断言：

1. 评审版 8 节结构齐（有来源的节）
2. DDL 存在；涉及迁移时 DML 存在
3. 新增接口为完整 schema；变更接口为 diff 对照
4. 状态机内容出现在"整体设计思路"而非独立节
5. "测试影响"含受影响的现有功能清单
6. 文件头有"以主方案为准，请勿直接编辑"标注
7. 主方案变更后评审版被重生成（内容随变更更新）
8. 说"不要评审版"后不生成且 plan.md 有记录
