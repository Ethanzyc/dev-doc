# 配方：通用骨架（generic-medium）

> **适用场景**：新模块、技改、重构、对外提供接口。
> 重量判定为"中"或"重"的方案默认用此配方。
> 后端领域决策点引用 `_backend-domain.md`。

---

## 文档结构（9 节 + 实现速查）

### 1. 需求背景

**写什么**：问题描述、现状分析、存在的问题、改进必要性。

**不该写什么**：不要复制 PRD 原文，要提炼"为什么要做"。

### 2. 需求说明

**写什么**：核心需求、具体要求、业务场景。

**不该写什么**：不要罗列所有功能点，聚焦"这个方案要解决的核心问题"。

### 3. 技术方案

这是核心章节，包含多个子章节：

#### 3.1 整体设计思路
- 架构图用 mermaid `flowchart`（见 `mermaid-checklist.md`）
- 1-2 段说明设计主线
- 轻方案可薄写，重方案必深写

#### 3.2 数据模型
- DDL + 索引 + 约束
- **遵循 `_backend-domain.md` 的 DDL 规范**（命名/主键/字段类型走团队规范，从规范源加载，Phase 1.3.0 探测；可能是 `conventions/sql.md` 或 `.claude/rules/sql.md`）
- 每个索引说明服务哪个查询
- DDL 用代码块包裹

#### 3.3 接口契约
- 路径/方法/请求响应/错误码/幂等性
- **遵循 `_backend-domain.md` 的接口规范**
- 精确的 schema（字段/类型/必填/取值范围）

#### 3.4 状态机
- 枚举 + mermaid `stateDiagram-v2` 流转图
- **文字说明**每个流转的触发条件 + 副作用 + 守卫条件（呼应 `_backend-domain.md` 决策点 5）

#### 3.5 关键流程
- 核心算法/流程的步骤化描述
- 复杂流程配 mermaid `sequenceDiagram`

### 4. 改动点

用表格（见 `_backend-domain.md` 的改动清单格式）：
| 类型 | 内容 |
| 删除 | ... |
| 改造 | ... |
| 新增 | ... |
| 接口变更 | ... |

### 5. 数据库变更

- 表结构变更（含 DDL）
- 索引变更
- 数据迁移方案（存量数据怎么处理）
- **回滚方案**（DDL 怎么回退、数据怎么恢复）

### 6. 测试方案

- 引用团队测试规范（走规范源：`.claude/rules/test.md` 或 `conventions/test.md`）
- 单元测试：测试类 + 覆盖场景
- 集成测试：测试场景 + 数据准备方式
- **具体**，不写"编写单元测试保证质量"（呼应 `anti-ai-signs.md` 第 10 条）

### 7. 上线方案

- 灰度策略（如有）
- 应急预案
- 回滚方案
- **监控指标仅在需求明确提出或对业务影响重大时才写**，不要写常规的耗时/失败率指标

### 8. 风险评估

用表格：

| 风险类型 | 描述 | 缓解措施 |
|---|---|---|
| 技术风险 | ... | ... |
| 业务风险 | ... | ... |
| 数据风险 | ... | ... |
| 性能风险 | ... | ... |

### 9. 工时评估

按接口粒度，引用 `_backend-domain.md` 的工时表和输出格式。

### 10. 实现速查

**这一节是索引，不是新内容**。给编码 AI 快速定位硬契约：

```markdown
### 10. 实现速查
- 数据模型（DDL）：见 3.2
- 接口契约：见 3.3
- 状态机：见 3.4
- 关键流程：见 3.5
- 改动清单：见 4
- 数据库变更（DDL/迁移/回滚）：见 5
- 工时评估：见 9
```

## 章节深浅表（由重量分级决定）

plan.md 的"章节规划"表会标注每章深浅。具体含义：

| 深浅 | 含义 |
|---|---|
| **深写** | 完整论证 + 细节 + trade-off |
| **正常** | 标准内容，点到为止的论证 |
| **薄写** | 1-2 段，不展开论证 |
| **跳过** | 不写该章节 |

各重量对应的默认深浅：

| 章节 | 轻 | 中 | 重 |
|---|---|---|---|
| 1. 需求背景 | 薄写 | 正常 | 正常 |
| 3.1 整体架构 | 跳过 | 薄写 | 深写 |
| 3.2 数据模型 | 深写（核心） | 深写 | 深写 |
| 3.3 接口契约 | 深写（核心） | 深写 | 深写 |
| 3.4 状态机 | 按需 | 正常 | 深写 |
| 3.5 关键流程 | 按需 | 正常 | 深写 |
| 4. 改动点 | 深写 | 深写 | 深写 |
| 5. 数据库变更 | 按需 | 正常 | 深写 |
| 6. 测试方案 | 薄写 | 正常 | 深写 |
| 7. 上线方案 | 薄写 | 正常 | 深写 |
| 8. 风险评估 | 薄写 | 正常 | 深写 |
| 9. 工时评估 | 深写 | 深写 | 深写 |

> "按需" = 有则写，无则跳过（比如轻方案可能不涉及状态机）。
